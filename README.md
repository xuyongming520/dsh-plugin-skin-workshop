# 皮肤工坊 · Skin Workshop 2.9.0

一个 DSH 界面插件：换皮肤（背景壁纸 + 面板材质）、换主题（配色与控件形状），自由组合，可试穿、保存、导出分享。
**不联网、不上传**：壁纸只在本机压缩，皮肤只存在你自己的浏览器里。

## 安装

要求 **DSH 0.2.2-rc.1 及以上、0.3.0 以下**（插件声明里写死的兼容范围）。

在 DSH 的「添加插件」输入框里粘贴仓库地址：

```
https://github.com/xuyongming520/dsh-plugin-skin-workshop
```

允许授权提示，装完按 `Cmd + R` 刷新。之后左侧栏和「设置」里都会出现**皮肤工坊**。

也可以下载 `local-violet-skin-2.5.0.tgz` 解压成文件夹，把**文件夹绝对路径**粘进同一个输入框（这种方式是软链接安装，文件夹不能移动或删除）。

## 2.9.0 两处首装/滚动的修复

1. **第一次安装时，第一屏是「已选好的内置背景」**。默认搭配里带了「雾光渐变」，所以新用户打开就看到一张背景卡片，找不到上传入口。现在新用户的草稿从「无背景」开始，第一屏的正中央就是上传区；内置背景作为备选排在下面。
2. **滚动插件列表时，吸顶标题变成一条纯白横带**。吸顶背板原来固定取 95% 不透明度（只为了保证标签可读），低遮罩皮肤下就和白条没区别。现在它跟随皮肤的正文遮罩：`正文遮罩 + 10%`、下限 40%，并保留模糊。例如遮罩 45% 时吸顶条是 55%，壁纸透得上来。

页面最下面原本有一行「主题 原生风格 ＋ 背景 雾光渐变 ＋ 材质 磨砂玻璃·55%」。既然改动已经即时可见、页签本身也说明了在改什么，这行只是重复，已删除。

## 2.8.1 「更多」去掉

「保存与分享」里只剩「另存为副本」一个次要按钮，还藏在「更多」里就不划算了——直接放出来，和「导出分享包」「试穿」并排。「删除这款皮肤」只在选中一款已保存的皮肤时出现。

## 2.8.0 撤销补上，底部改成「保存与分享」

反馈：① 提示写着「点撤销」，但按钮没出现；② 底下那块看不懂在干什么。

1. **撤销真的有了**：之前只有「换过皮肤」时才存撤销快照，第一次换外观时快照为空，按钮就不渲染。现在每次即时应用都会记一个快照（没有上一个外观就回退到 DSH 默认），提示条右侧始终有「撤销」。
2. **底部改成「保存与分享」**：皮肤名称不再孤零零挂着。这一块现在说清楚两件事——「保存到我的皮肤」存下来下次用，「导出分享包」生成 `.dsh-skin.json` 发给别人导入。试穿和「更多（另存为副本 / 删除）」退到次要位置。
3. **「保存并应用」这个概念取消了**：既然改什么都立刻生效，就没有「应用」这一步；剩下的只有「保存」，是存档不是生效。
4. **拆开「正在用的外观」和「我的皮肤」**：即时应用写进一个固定的当前槽位，不会每点一次主题就往收藏里塞一条、也不会覆盖你命名过的皮肤。删除一款已保存的皮肤不会改变正在使用的外观；要回到默认用顶部的「恢复默认」。
5. 滑杆、下拉这类控件也改成即时生效（300ms 防抖），只在拖动结束时写一次。

## 2.7.0 选好即生效

上一版把按钮收进了「更多」，但底部仍留着一整套保存流程。这一版改的是**交互模型**：

- **选好就生效**：上传壁纸、点内置背景、切主题、套用配套、点「更通透 / 更清晰」、拖「正文阅读遮罩」，都**立刻应用到真实界面**，不需要再点保存。
- **一键撤销**：每次即时生效后，提示条右侧有「撤销」，一步回到上一个外观。
- **保存按钮按需出现**：只有「还没生效的改动」（比如只在「高级」里拖了滑杆、或改了皮肤名称、或刚导入了一个分享包）才出现「保存并应用」；没有待应用的改动时，这里只显示「已应用」。
- **文案改成对用户说的话**：第一行是「挑一张喜欢的图，工作台立刻换个心情。」，不再解释内部结构。
- 上传/切换主题时会自动结束正在进行的 60 秒试穿，避免试穿浮条和已生效的皮肤打架。

## 2.6.0 按使用者反馈简化

来自第一位使用者的四条反馈，逐条落实：

1. **上传后没有回显** → 上传成功后立刻显示缩略图卡片，标题变成「✓ 壁纸已上传」，旁边给出「换一张 / 移除背景」。拖拽替换也可以直接丢在这张卡片上。
2. **恢复默认位置太深** → 移到页面顶部右侧，和「当前外观」并排。
3. **次要参数太杂** → 首屏只留：背景卡片（或上传区）、三张内置背景、正文阅读遮罩、更通透 / 更清晰。壁纸细节（不透明度、模糊、填充、位置、缩放、压暗）和面板材质（材质、不透明度、磨砂）收进「高级：壁纸与面板」。
4. **底部按钮太乱** → 主操作只剩两个：**试穿 60 秒**、**保存并应用**；仅保存 / 另存为 / 导出分享包 / 删除 折进「更多」。皮肤名称移到按钮上方。

## 2.5.0 每个主题都有配套皮肤

主题原来只换配色与控件形状。现在四张主题卡各带一个 **「套用配套」** 按钮，一次换上该主题的完整套装：

| 主题 | 配套背景 | 配套材质 |
| --- | --- | --- |
| 原生风格 | 雾光渐变 | 磨砂玻璃 55% / 阅读遮罩 45% |
| 现代简约 | 雾光渐变 | 磨砂玻璃 55% / 阅读遮罩 45% |
| XP 复古 | 晴空草坡 | 不透明面板 |
| 像素方块 | 方块山谷 | 不透明面板 |

两种用法分开保留：

- 点卡片的**主体**（缩略图与名称）= 只换主题，保留你自己的壁纸和材质。
- 点 **「套用配套」** = 主题 + 背景 + 材质一起换，等于载入一款成套皮肤；有未保存修改时先确认。

配套内容来自快速搭配里的同一份定义，不额外存数据，导出的皮肤包格式不变。

## 2.1.2 遮罩变薄

有反馈说壁纸虽然透出来了，但整体像蒙着一层厚白纱。用纯色壁纸做标定实测，白色覆盖率是这样的：

| 区域 | 2.1.1 的实测 | 原因 |
| --- | --- | --- |
| 侧栏整列 | 75% 白 | 面板不透明度 75% |
| 正文整列 | 80% 白 | 正文阅读遮罩 80%，盖满中栏 |
| 输入框卡片 | 75% 白 + 磨砂 | 面板材质 |

两列叠加后壁纸只剩约 20% 的可见度。而「只换背景 / 简约玻璃」快速搭配的默认值正好是 75/80，界面还会在遮罩低于 80% 时提示“建议设为 80% 以上”，等于一路把人推向厚遮罩。

现在：

- 快速搭配默认改成 **面板 55% / 阅读遮罩 45%**，壁纸在正文里能看到约 55%。
- 「材质与阅读」新增 **更通透**（面板 40% / 遮罩 30%）与 **更清晰**（80% / 80%）两个一键调节，只改这两个数，不动壁纸。
- 阅读遮罩旁直接显示「现在还剩 X% 可见」，把滑杆和实际效果对上。
- 提醒阈值从 80% 降到 30%：只有压到 30% 以下才提示小字可能发花，不再把正常取值说成有问题。
- 已保存的皮肤不会被自动改写；打开工坊点一次「更通透」再保存即可，壁纸不用重新上传。

## 2.1.1 聊天页修复

真实聊天页是 `main → main.conversation → ConversationRoot`。2.1.0 的隔离测试省略了中间会话插槽，导致只处理直接位于 main 下的根节点，实际聊天页仍被整块不透明底色遮住。现在针对会话插槽内、含直接 header 插槽的会话根补齐透明化，不清除任意第三方页面底色。阅读遮罩仍独立保护正文，参数、壁纸与数据格式不变。

原生回归已改为真实会话层级，并加载当前安装 DSH 的完整会话 CSS；用新旧客户端做聊天顶部、正文、输入区周围的壁纸像素对照，避免仅凭侧栏或模拟图判断成功。

**换肤是总入口，一套搭配 = 主题风格 + 背景壁纸 + 材质与阅读设置。**

三部分可以独立编辑：只换背景不必换主题；换主题不再覆盖壁纸；玻璃是材质，不再与 XP、像素风混作同一级主题。整套搭配仍可试穿、保存、导出分享。

这是原「紫雾皮肤」的原地升级，不是另装第三方插件。npm 包名、插件接线、页面入口仍沿用 `@local/violet-skin` / `skin-workshop`。

## 先试一次：保留原生主题，只换背景

1. 刷新 DSH 页面，点左侧「皮肤工坊」。设置中也有同页入口。
2. 打开「我的皮肤」页签，「快速搭配」里点 **只换背景**。它选用原生风格，保留宿主配色与控件形状。
3. 回到「换皮肤」页签，把原始 PNG / JPEG / WebP 拖进虚线框（或点击选择）。也可以先点一张内置背景。可调壁纸不透明度、模糊、铺放方式、位置、缩放与压暗。
4. 往下到「材质与阅读」调整面板不透明度、磨砂强度、正文阅读遮罩；想更像参考作品就点「更通透」。
5. 点「试穿 60 秒」，可以去聊天页或插件页查看整窗效果。右下角可撤销，到时也会自动恢复。
6. 满意后点「保存并应用」或浮条「保留并应用」。只收进库中，点「仅保存 / 保存修改」。

**选择与编辑只更新示意，不会立即覆盖整个界面。** 开始试穿后再拖滑杆，会实时更新整窗效果，但不会延长截止时间，也不会自动保存。

初次使用不会强行应用新搭配。更新时，已保存并应用的旧皮肤会继续使用，而非被默认方案替换。原生强调色、明暗模式、字号、字体仍由 DSH 管理，不再另造一套颜色选择器。

## 两块分别控制什么

| 区域 | 控制内容 | 不会顺带改变 |
| --- | --- | --- |
| 换皮肤 · 背景壁纸 | 无背景、原创内置背景、自己的图片；图片浓淡与铺放效果 | 主题、面板与阅读遮罩 |
| 换皮肤 · 材质与阅读 | 玻璃 / 不透明面板、面板不透明度、磨砂、独立正文遮罩 | 主题与壁纸 |
| 换主题 | 原生、现代简约、XP 复古、像素方块；配色与控件形状 | 壁纸、材质、阅读遮罩、方案名称 |

页签：**换皮肤**放壁纸和材质（默认打开，上传在最上面）、**换主题**放配色和控件形状、**我的皮肤**存整套搭配并可导入 / 导出分享包，快速搭配也在这一页。

- **原生风格**：不覆盖任何宿主主题 token，读取当前宿主配色；保留原生圆角、边框、控件阴影与发送按钮形状。此时圆角/描边/阴影编辑禁用。背景与材质仍可独立调整。
- **现代简约**：原「玻璃壁纸」的控件风格，内部 id `glass` 保留以兼容旧数据；可以搭配玻璃，也可以搭配不透明面板或无背景。
- **XP 复古 / 像素方块**：风格化原创实现，不是 Windows 或游戏原界面、原素材的 1:1 复制。也可以搭配自己的照片与玻璃材质。
- **快速搭配**是四个完整起点：只换背景、简约玻璃、XP 复古、像素方块。它在「我的皮肤」页签里、缩成 2×2，载入会替换整套草稿，有未保存修改时先确认；单项切换只改变对应部分。

## 为什么有三种“不透明度”

| 调节项 | 含义 |
| --- | --- |
| 壁纸不透明度 `0–100%` | 只让图片向当前主题底色淡出；0% 看不到图片，100% 保留原图浓度 |
| 面板不透明度 `0–100%` | 侧栏、输入框与气泡等面板的填充；越低越透，磨砂单独调 |
| 正文阅读遮罩 `0–100%` | 正文区域的独立底板；浅色提亮、深色压暗，不带动侧栏和输入框 |

阅读遮罩不再被面板滑杆暗中联动。不透明材质只关闭面板透光与磨砂，正文遮罩仍能独立调节。

正文遮罩低于 30% 时，工坊会提醒复杂壁纸上的小字可能发花；这是允许用户自主选择的效果，**低遮罩下不保证文字对比度**。日常 40% 左右既能看清壁纸，也能读字；长时间纯阅读可以点「更清晰」。菜单、弹窗与提示保留安全底色；原生插件页滚动标题有至少 95% 的保护底板，避免后面的文字穿透重叠。

## 保存、试穿与分享

- 保存、改名称后保存修改、另存为/复制、删除；最多 16 款，并有本地总容量保护。
- 同一窗口离开并返回工坊保留草稿。刷新/关闭前请保存或导出分享包。
- 60 秒试穿不写持久化存储。后台标签被节流时，返回页面会按真实截止时间检查回退。
- 只保存不应用，不会悄悄覆盖已应用快照；保存失败会报错，不会宣称成功。
- 恢复 DSH 默认不删除库；删除当前正在用的皮肤也会恢复原生外观。
- 导出包含当前编辑器的主题、壁纸、材质、阅读遮罩及尚未保存的修改。图片随包嵌入，不依赖本机路径。分享前确认图片内容和使用权限。
- 分享工具用完整插件目录或 `.tgz`；接收者安装皮肤工坊后，再导入 `.dsh-skin.json`。导入只进入草稿，不自动应用。

## 2.1 数据兼容

- 新皮肤包使用 `format: "dsh-skin-workshop"`、`version: 2`，显式保存 `readingOpacity` 和 `wallpaper.opacity`，并支持原生风格。
- **继续读取 v1 包及旧本地库**。旧库在内存中规范化，启动不写回；只有明确保存时才写为 v2。
- v1 壁纸不透明度补为 100%。v1 玻璃材质的阅读遮罩补为 `max(80, 原面板不透明度)`，不透明材质补为 80%，保持 2.0.1 的实际效果不变。
- 旧皮肤名称、图片、已保存 id、独立的已应用快照全部保留；未引入新存储位置。物理键仍为 `dsh.skin-workshop.library.v1`，其中的文档版本可以是 1 或 2。
- 新包需要 **2.1.0 或更新版本**导入，不能承诺旧版工坊识别 v2。降级前请保留旧导出或备份。
- 三个原 v1 示例保留作为兼容样例，另附 v2 的「只换背景」示例。
- 更早的 `dsh.violet-skin.colors.v1` 数据不读取也不删除。

## 数据与安全边界

- 所有图片在浏览器本地处理，无遥测、无上传接口、无外部资源请求。
- 壁纸上传仅 PNG、JPEG、WebP；原图最多 10 MiB / 3200 万像素 / 单边 12000px；重编码最长边 1920px，复杂大图继续缩小。WebP 动画会静态化。
- 内嵌图片不超过 720,000 字符；单个导入包最多 1,100,000 bytes；库 JSON 最多 2,100,000 字符。同源其他插件的数据也占浏览器配额。
- 皮肤包是严格校验的数据，未知字段、任意 CSS / JavaScript / hooks、SVG、远程图片地址、第三方主题格式一律拒绝。v1/v2 分别校验，不用“填默认值”掩盖损坏的 v2 字段。
- 损坏旧库不会静默删除；下一次成功保存前备份到 `dsh.skin-workshop.recovery.v1`，已有不同备份则停止写入。
- 恢复默认遇到存储故障时仍先清除当前窗口效果，并提示刷新可能恢复旧设置。
- 数据只在当前浏览器 / 设备 / 页面源中保存，不跨设备同步。清理站点数据前请导出。

## 覆盖范围与限制

适配 DSH `0.2.2-rc.1` / DS Bot `0.3.2` 的现有主题、插槽与 DOM 结构。React 和宿主模块通过 peerDependencies 由宿主提供，不重复打包运行库。

- 壁纸在整窗底层；适配原生侧栏、插件页标题、原生会话、DS Bot 左侧栏、标题胶囊、聊天气泡和输入框等。
- 每个大面板只画一层材质，原生侧栏内部不重复叠色。
- 模糊不放在原生布局祖先上；装饰背板和实际卡片负责模糊，避免改变窗口标题栏和浮层的 fixed 定位。
- 不改布局尺寸、导航位置、窗口拖动区、按钮功能、发送逻辑、状态色或原生强调色；DS Bot 平铺消息模式不会被强制改成气泡。
- 第三方页面、iframe 有自己的样式或文档，不保证整套适配。不要同时开多个全局换肤插件。
- 示例是效果示意，不是用户聊天截图；与实际窗口比例不同，背景裁切和原生配色可能不同。整屏明暗始终跟随 DSH。
- 暂不增加动态/视频壁纸、多图轮播、远程图地址、音乐/歌词、字体上传、任意 CSS、在线市场或账户同步。这轮优先把静态背景与主题的组合做顺。
- 选择器是版本兼容层，不是永久稳定 API，DSH / DS Bot 大版本更新应复测。
